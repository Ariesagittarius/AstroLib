为了提升教材数字化过程中的排版校对效率，AstroLib 在本地开发模式（`astro dev`）下内置了在线可视化 MDX 精修与全书模块结构检查两组工程工具。

---

## 1. 在线可视化 MDX 编辑模式（EditorMode）

在传统的静态站点开发中，修改排版瑕疵需要：在浏览器中发现问题 → 切回 VS Code → 全局搜词或推测行号 → 修改保存 → 等待热重载。

AstroLib 内置了从浏览器直接回写本地磁盘源文件的双向编辑能力：

### 1.1 工作原理
1. **编译期源码标记**：在 `astro dev` 运行时，Rehype 插件（`src/utils/mdx-editor/`）自动在 AST 节点注入段落的源文件物理路径（`data-src-file`）与起始行号（`data-src-line`）；
2. **浏览器交互**：在页面中唤起精修模式后，划选或点击需要修改的段落，界面将调出轻量 Markdown/KaTeX 编辑面板；
3. **本地安全回写**：点击保存后，前端通过 POST 请求向 Vite 本地开发服务器专有端点发送内容差量，服务端直接将修改安全写入磁盘中的 `.mdx` 文件，并立即触发 Vite HMR 实时热刷新。

### 1.2 开启与使用
- **开关配置**：确保 `src/config/features.config.mjs` 中 `editor.enabled = true`（默认仅在 dev 模式生效，生产打包零注入）；
- **激活方式**：点击顶栏右上角“九点工具箱”，勾选“在线精修模式”（或按下绑定快捷键）；
- **操作流程**：点击正文任意段落，在右侧滑出的浮层中微调 LaTeX 公式或修补字句，点击“保存修改”即可瞬间生效并持久化到代码库。

## 2. 全书模块检查与健康度巡检（ModuleInspector）

在教材规模达到数十万字、上百个知识卡片时，极易发生例题编号重复、定理标签冲突或卡片提前闭合导致的结构损坏。

AstroLib 提供了全书维度的模块检查工具：

### 2.1 检查能力
- **全书模块索引**：在面板中集中罗列当前图书的所有 `<Knowledge>`（定理/定义）、`<Example>`（例题）、`<Method>`（方法总结）与插图；
- **重复编号告警**：自动检测是否存在重名的例题（如同一章内出现两个“例 2.3”）；
- **孤儿推导排查**：识别是否有 `<Solution>` 未与 `<Example>` 正确配对，或推导过程脱离卡片容器；
- **一键精准定位**：点击列表中任意模块条目，页面将平滑滚动并闪烁高亮目标卡片。

### 2.2 开启方式
- 确保 `src/config/features.config.mjs` 中 `moduleInspector.enabled = true`；
- 在顶栏工具箱中点击“模块检查”，界面将在右侧 Sideload Dock 调出检查面板。
