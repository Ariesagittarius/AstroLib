## 2.4 中位数

数字列表的中位数是它的第 50 个百分位：一半数字比它大，一半比它小。例如，[45,1,10,30,25]的中位数是25，因为这是数字按顺序排列时位于中间的元素。如果列表的长度为偶数，则中间元素有两种选择，在这种情况下，我们选择两个中较小的一个。

中位数的目的是通过单个典型值来总结一组数字。平均值也非常常用于此，但中位数在某种意义上更典型的数据：与平均值不同，它始终是数据值之一，并且对异常值不太敏感。例如，由一百个 1 组成的列表的中位数（正确地）是 1，平均值也是如此。然而，如果这些数字中只有一个被意外破坏为 10,000，平均值就会飙升至 100 以上，而中位数不受影响。

计算 n 个数字的中位数很容易：只需对它们进行排序即可。缺点是这需要 $O ( n \log n )$ 时间，而我们理想情况下希望是线性的。我们有理由充满希望，因为排序所做的工作比我们真正需要的要多得多——我们只想要中间元素，而不关心其余元素的相对顺序。

矛盾的是，在寻找递归解决方案时，处理问题的更一般版本通常更容易，原因很简单，这提供了更强大的递归步骤。在我们的例子中，我们将考虑的概括是选择。

精选

输入：数字列表 $S ;$ 整数 $k$

输出：S 的第 k 个最小元素

例如， $\mathbf { i f } \ k = 1$ ，寻找 S 的最小值，而 $\mathrm { i f } k = \lfloor | S | / 2 \rfloor$ ，它是中位数。

## 用于选择的随机分而治之算法

这是一种分而治之的选择方法。对于任何数字 $v ,$，想象将列表 S 分为三类：小于 v 的元素、等于 v 的元素（可能有重复）和大于 v 的元素。分别将这些元素称为 $S _ { L } , S _ { v }$ 和 $S _ { R }$。例如，如果数组

在 $v = 5$ 上分割，生成的三个子数组是

$$
S _ {L}: \quad \boxed {2} \boxed {4} \boxed {1}
$$

$$
S _ {v}: \quad \boxed {5} \boxed {5}
$$

<table> <tr> <td> $S_{R}$ :</td> <td>36</td> <td>21</td> <td>8</td> <td>13</td> <td>11</td> <td>20</td> </tr> </table>

搜索可以立即缩小到这些子列表之一。比如说，如果我们想要 $S ,$ 的第八小元素，我们知道它一定是自 $| S _ { L } | + | S _ { v } | = 5$ 以来 $S _ { R }$ 的第三小元素。即，选择 $( S , 8 ) \ = \ \mathrm { s e l e c t i o n } ( S _ { R } , 3 )$ 。更一般地说，通过检查 k 与子数组的大小，我们可以快速确定其中哪个包含所需的元素：

$$
\mathbf {s e l e c t i o n} (S, k) = \left\{ \begin{array}{l l} \mathbf {s e l e c t i o n} (S _ {L}, k) & \text {if} k \leq | S _ {L} | \\ v & \text {if} | S _ {L} | <   k \leq | S _ {L} | + | S _ {v} | \\ \mathbf {s e l e c t i o n} (S _ {R}, k - | S _ {L} | - | S _ {v} |) & \text {if} k > | S _ {L} | + | S _ {v} |. \end{array} \right.
$$

三个子列表 $S _ { L } , S _ { v }$ 和 $S _ { R }$ 可以在线性时间内从 S 计算出来；事实上，这种计算甚至可以就地完成，即无需分配新内存（练习 2.15）。然后我们在适当的子列表上递归。因此，分割的效果是将元素数量从 S 减少到最多 max $\{ \vert S _ { L } \vert , \vert S _ { R } \vert \}$

我们的分而治之选择算法现在已经完全指定，除了如何选择 v 的关键细节。它应该被快速选择，并且它应该大幅缩小数组，理想的情况是 $\begin{array} { r } { | S _ { L } | , | S _ { R } | \approx \frac { 1 } { 2 } | S | } \end{array}$ 。如果我们总能保证这种情况，我们将得到运行时间

$$
T (n) = T (n / 2) + O (n),
$$

这是所需的线性。但这需要选择v作为中位数，这是我们的最终目标！相反，我们遵循一个更简单的替代方案：我们从 S 中随机选择 v。

## 效率分析

当然，我们算法的运行时间取决于 v 的随机选择。有可能由于持续的运气不好，我们一直选择 v 作为数组的最大元素（或最小元素），从而每次只将数组缩小一个元素。在前面的示例中，我们可能首先选择 $v = 3 6$ ，然后选择 $v = 2 1$ ，依此类推。这种最坏的情况将迫使我们的选择算法执行

$$
n + (n - 1) + (n - 2) + \dots + \frac {n}{2} = \Theta (n ^ {2})
$$

操作（计算中位数时），但这种情况极不可能发生。同样不可能的是我们之前讨论过的最佳情况，其中每个随机选择的 v 恰好将数组完美地分成两半，导致运行时间为 $O ( n )$ 。在从 $O ( n )$ 到 $\Theta ( n ^ { 2 } )$ 的频谱中，平均运行时间在哪里？幸运的是，它非常接近最佳情况时间。

为了区分 $v ,$ 的幸运选择和不幸选择，如果 v 位于所选数组的第 25 到 75 个百分位数内，我们将其称为良好。我们喜欢 v 的这些选择，因为它们确保子列表 $S _ { L }$ 和 $S _ { R }$ 的大小最多为 $S$ 的四分之三（你明白为什么吗？），从而使数组大幅缩小。幸运的是，好的 v 是丰富的：任何列表的一半元素必须位于第 25 到 75 个百分位数之间！

假设随机选择的 v 有 50% 的机会是好的，那么我们平均需要选择多少个 v 才能得到一个好的 v？这是一个更熟悉的重新表述（另见练习 1.34）：

平均来说，一枚公平的硬币需要抛掷两次才能看到“正面”。

</Knowledge>

令 E 为看到正面之前预期的抛掷次数。我们当然需要至少抛掷一次，如果是正面，我们就完成了。如果是尾部（出现概率为 $1 / 2 )$ ，我们需要重复。因此 $\begin{array} { r } { E = 1 + \frac { 1 } { 2 } E } \end{array}$ ，结果为 $E = 2 . \ |$

因此，平均经过两次分割操作后，数组最多会缩小到其大小的四分之三。令 $T ( n )$ 为大小为 n 的数组上的预期运行时间，我们得到

$$
T (n) \leq T (3 n / 4) + O (n).
$$

接下来，取以下语句两边的期望值：

大小为 n 的数组所花费的时间

$\leq$（大小为 3n/4 的数组所花费的时间）+（将数组大小减少到 $\leq 3 n / 4 )$ 的时间）

并且，对于右侧，使用熟悉的属性，即总和的期望是 $o f t h e$ 期望之和。

从这个递归中，我们得出结论：$T ( n ) = O ( n )$：对于任何输入，我们的算法平均在线性步数之后返回正确的答案。

比较排序和中值查找算法，我们注意到，除了常见的分而治之的哲学和结构之外，它们是完全相反的。归并排序以最方便的方式将数组分成两部分（前半部分，后半部分），而不考虑每一半中元素的大小；但随后它很难将排序后的子数组放在一起。相比之下，中值算法对其分裂非常谨慎（首先是较小的数字，然后是较大的数字），但其工作以递归调用结束。

快速排序是一种排序算法，其分割数组的方式与中位数算法完全相同；一旦通过两次递归调用对子数组进行排序，就没有什么可做的了。它的最坏情况性能是 $\Theta ( n ^ { 2 } )$ ，就像中值查找一样。但可以证明（练习2.24）它的平均情况是 $O ( n \log n )$；此外，根据经验，它优于其他排序算法。这使得快速排序成为许多应用程序中的最爱，例如，它是对巨大文件进行排序的代码的基础。

</Knowledge>
