## 第 2 章：分治算法

分治策略通过以下方式解决问题：

1. 将其分解为子问题，这些子问题本身就是同一类型问题的较小实例

2. 递归解决这些子问题

3. 适当组合他们的答案

真正的工作是在三个不同的地方零碎完成的：将问题划分为子问题；在递归的最后阶段，当子问题很小以至于可以直接解决时；以及将部分答案粘合在一起。它们由算法的核心递归结构结合在一起并协调。

作为一个介绍性的例子，我们将看到这种技术如何产生一种新的数字乘法算法，它比我们在小学学到的方法要高效得多！

## 2.1 乘法

数学家卡尔·弗里德里希·高斯（Carl Friedrich Gauss，1777-1855）曾经注意到，虽然两个复数的乘积

$$
(a + b i) (c + d i) = a c - b d + (b c + a d) i
$$

似乎涉及四个实数乘法，实际上只需三个即可完成： $^ { a c , }$ bd 和 $( a + b ) ( c + d )$ ，因为

$$
b c + a d = (a + b) (c + d) - a c - b d.
$$

按照我们的大 O 思维方式，将乘法次数从四次减少到三次似乎浪费了聪明才智。但当递归应用时，这种适度的改进就会变得非常显着。

让我们远离复数，看看这对常规乘法有何帮助。假设 x 和 y 是两个 n 位整数，并为了方便起见假设 n 是 2 的幂（更一般的情况几乎没有任何不同）。作为将 x 和 y 相乘的第一步，将它们分成左右两半，长度为 $n / 2$ 位：

$$
x = \boxed {x _ {L}} \boxed {x _ {R}} = 2 ^ {n / 2} x _ {L} + x _ {R}
$$

$$
y = \boxed {y _ {L}} \boxed {y _ {R}} = 2 ^ {n / 2} y _ {L} + y _ {R}.
$$

例如，如果 $x = 1 0 1 1 0 1 1 0 _ { 2 }$ （下标 2 表示“二进制”），则 $x _ { L } = 1 0 1 1 _ { 2 } , x _ { R } = 0 1 1 0 _ { 2 }$ 和 $x = 1 0 1 1 _ { 2 } \times 2 ^ { 4 } + 0 1 1 0 _ { 2 }$ 。 $\cdot _ { x }$ 和 $y$ 的乘积可以重写为

$$
x y = (2 ^ {n / 2} x _ {L} + x _ {R}) (2 ^ {n / 2} y _ {L} + y _ {R}) = 2 ^ {n} x _ {L} y _ {L} + 2 ^ {n / 2} (x _ {L} y _ {R} + x _ {R} y _ {L}) + x _ {R} y _ {R}.
$$

我们将通过右侧的表达式计算 $x y$。加法需要线性时间，乘以 2 的幂也需要线性时间（这只是左移）。重要的操作是四个 $n / 2 – \mathrm { b i t }$ 乘法，$x _ { L } y _ { L } , \ x _ { L } y _ { R } , \ x _ { R } y _ { L } , \ x _ { R } y _ { R } ;$，我们可以通过四个递归调用来处理这些操作。因此，我们的 n 位数字相乘方法首先通过递归调用将这四对 $n / 2$ 位数字相乘（四个大小一半的子问题），然后在 $O ( n )$ 时间内计算前面的表达式。将n位输入上的总运行时间写入 $T ( n )$，我们得到递推关系

$$
T (n) = 4 T (n / 2) + O (n).
$$

我们很快就会看到解决此类方程的一般策略。与此同时，这个特殊的计算结果为 $O ( n ^ { 2 } )$ ，与传统小学乘法技术的运行时间相同。所以我们有一个全新的算法，但我们在效率方面还没有取得任何进展。我们的方法如何加速？

这就是高斯诡计的由来。尽管 xy 的表达式似乎需要四次 $n / 2 { \cdot } \mathrm { b i t }$ 乘法，但与之前一样，只需 3 次即可： $x _ { L } y _ { L } , x _ { R } y _ { R } $ ，以及自 $x _ { L } y _ { R } + x _ { R } y _ { L } = ( x _ { L } + x _ { R } ) ( y _ { L } + y _ { R } ) - x _ { L } y _ { L } - x _ { R } y _ { R }$ 以来的 $( x _ { L } + x _ { R } ) ( y _ { L } + y _ { R } )$ 。由此产生的算法如图 2.1 所示，具有改进的运行时间 $\mathbf { o f } ^ { 1 }$

$$
T (n) = 3 T (n / 2) + O (n).
$$

关键是，现在常数因子改进（从 4 到 3）发生在递归的每个级别，这种复合效应导致 $O ( n ^ { 1 . 5 9 } )$ 的时间界限显着降低

该运行时间可以通过查看算法的递归调用模式得出，该模式形成树结构，如图 2.2 所示。让我们尝试了解这棵树的形状。 $\mathbf { A t }$ 每个连续的递归级别子问题的大小都会减半。在 $( \log _ { 2 } n ) ^ { \mathrm { t h } }$ 级别，子问题的大小降至 1，因此递归结束。因此，树的高度为 $\log _ { 2 } n$，分支因子为3——每个问题递归地产生三个较小的问题——结果是，在树的深度k处，有 $3 ^ { k }$ 子问题，每个子问题的大小为 $n / 2 ^ { k }$

对于每个子问题，在识别进一步的子问题并组合它们的答案时会完成线性工作量。因此，在树中深度 k 处花费的总时间为

$$
3 ^ {k} \times O \left(\frac {n}{2 ^ {k}}\right) = \left(\frac {3}{2}\right) ^ {k} \times O (n).
$$

$$
T (n) \leq 3 T (n / 2 + 1) + O (n)
$$

在最顶层，当 $k = 0$ 时，结果为 $O ( n )$ 。在底部，当 $k = \log _ { 2 } n _ { \mathrm { : } }$ 时，它是 $O ( 3 ^ { \log _ { 2 } n } )$ ，可以重写为 $O ( n ^ { \log _ { 2 } 3 } )$ （你明白为什么吗？）。在这两个端点之间，完成的工作以几何方式从 $O ( n )$ 增加到 $O ( n ^ { \log _ { 2 } 3 } )$ ，每级增加 $3 / 2$ 倍。任何增加的几何级数的总和，在一个常数因子内，只是级数的最后一项：这就是增加的速度（练习0.2）。因此，总体运行时间为 $O ( n ^ { \log _ { 2 } 3 } )$ ，大约为 $O ( n ^ { 1 . 5 9 } )$ 。

如果没有高斯技巧，递归树将具有相同的高度，但分支因子将为 4。将有 $4 ^ { \log _ { 2 } n } = n ^ { 2 }$ 叶子，因此运行时间至少是这么多。在分治算法中，子问题的数量转化为递归树的分支因子；该系数的微小变化会对运行时间产生很大影响。

实际注意事项：一直递归到 1 位通常没有意义。对于大多数处理器来说，16 位或 32 位乘法是单个运算，因此当数字进入此范围时，应将它们移交给内置过程。
