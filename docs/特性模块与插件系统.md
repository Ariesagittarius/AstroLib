# 特性模块与插件系统 — 设计与接入说明

> 目标：把全站「自定义功能」从散落各处收敛为一张表，让开发者在**构建层（build）**
> 按需启停工具，读者在**UI 层**按需使用，未启用功能**零打包/零注入**，从而实现性能最大化；
> 并为后期开发个人插件提供**最小可用的接入环境**（一个 manifest 即可接入）。

---

## 一、核心：Feature Registry（`src/config/features.config.mjs`）

这是全站功能的**唯一声明源**。每个功能是一个 manifest（由 `defineFeature` 定义并校验）。

```js
import { defineFeature } from './src/config/features.config.mjs';

export const features = {
  fonts: defineFeature({
    id: 'fonts',
    cat: 'reader',        // reader（读者偏好）/ extra（附加内容）/ dev（开发工具）
    label: '字体系统',
    desc: '读者可选字体档位 + 自托管思源 webfont',
    enabled: true,        // build 层开关；false → 该功能彻底不进入产物
    devOnly: false,       // 仅 dev 生效（如 editor）：有效启用 = enabled && IS_DEV
    ui: true,             // 是否在 UI 层向读者暴露（决定控件是否渲染）
    requires: ['theme'],  // 依赖的其他功能 id（元信息）
    config: { refs: 'static' }, // 该功能的构建参数（如引用联动模式）
  }),
};
```

导出工具：
- `features`：功能表（id → manifest）。
- `FEATURE_IDS`：所有功能 id。
- `isEffective(id)`：**有效启用** = `enabled && (!devOnly || IS_DEV)`。供 `astro.config.mjs` 构建期判断。
- `crossRefRefs()`：取 `crossRef.config.refs`（引用联动模式，供 rehypeCrossRef / PageSidebarOverride）。

> ⚠️ 组件（`.astro` frontmatter）请**直接读 `features.<id>.enabled` 布尔值**，不要在组件里
> 计算 devOnly（避免组件内引入 `process` 依赖）。本文件被 astro.config / 组件 / Node 脚本
> 共享，必须是**纯 ESM、无 Node API 之外副作用**的模块。

## 二、现有功能一览与装配处

| 功能 id | cat | enabled | devOnly | ui | build 层装配 | UI 层装配 |
|---|---|---|---|---|---|---|
| `katex` | reader | true | — | — | `astro.config.mjs` markdown 插件 + `customCss(katex.css)` | — |
| `theme` | reader | true | — | ✓ | `components.ThemeSelect`（VitePress 图标按钮）+ `vitepress-theme.css` | 主题按钮 |
| `fonts` | reader | true | — | ✓ | `customCss`（`@fontsource` 两套 + `fonts.css`） | 字体下拉（嵌在主题按钮旁；`ThemeSelectOverride` 内条件渲染） |
| `crossRef` | reader | true | — | — | `rehypeCrossRef` 插件（`refs` 取 `crossRefRefs()`） | — |
| `epub` | extra | true | — | ✓ | `scripts/generate-epub.mjs`（未启用则跳过生成） | 侧栏 + 首页下载链接（`SidebarOverride` / `index.astro`） |
| `editor` | dev | true | ✓ | — | `rehypeEditorAnnotate` + `dev-server-plugin`（仅 dev） | `FooterOverride` 渲染壳（仅 dev） |

## 三、构建层装配逻辑（`astro.config.mjs`）

`astro.config.mjs` 从 registry 读取，**动态组装** Starlight 配置：

- `remarkPlugins` / `rehypePlugins`：`katex` 开才加数学相关；`crossRef` 开才加 `rehypeCrossRef`；`isEffective('editor')` 才加编辑器注入。
- `customCss`：`katex`/`theme`/`fonts` 开关决定是否引入对应 CSS（**关闭字体则不打包 `@fontsource` 与 `fonts.css`**）。
- `components`：`theme` 开才覆盖 `ThemeSelect`（其余自定义骨架恒用）。
- `vite.plugins`：`isEffective('editor')` 才挂写回端点。

> 关闭某功能 = 不挂载对应插件/CSS/组件/生成脚本 → 该功能不进构建产物，性能最大化。
> 关键顺序（同特异性、同层、后加载者生效）不可乱：`katex` 先于 `custom.css`；
> `vitepress-theme` 于 `custom.css` 之后；`fonts.css` 必须最后。

## 四、UI 层装配逻辑

组件在 frontmatter 读 `features.<id>.enabled` 决定是否渲染控件（**不加新的统一面板**，保留现有 header 控件）：

- `ThemeSelectOverride.astro`：`{features.fonts.enabled && <FontSelect />}`。
- `SidebarOverride.astro` / `index.astro`：`features.epub.enabled` 决定是否探测/渲染 EPUB 下载链接。
- `FooterOverride.astro`：`{isDev && features.editor.enabled && <EditorMode />}`。

### 前端运行时功能开关（dev 专用）

除构建层开关外，项目还提供**前端运行时功能开关面板**（开发调试用，生产构建零输出）：

- 面板：`src/components/FeatureToggles.astro`（自包含 `<starlight-feature-toggles>` 自定义元素，挂载于顶栏 ThemeSelect 槽位——桌面 header 右侧动作区 / 移动端抽屉底部，仅 dev 渲染；页面上可同时渲染多个实例，各自管理自己的 ⚙ 开合与下拉面板）。
- 状态：`src/scripts/feature-toggles.ts`（localStorage `starlight-features` 持久化）。
- 行为：`有效启用 = 构建层 enabled（data-meta 注入） && 运行时未关闭`；对标记了 `[data-feature="<id>"]` 的元素显隐（`.dsh-feature-off` 隐藏），并门控字体（清/设 `<html data-font>`）与精修工具（`window.__dshFeatureEditorAllowed`）。
- 可运行时切换：`theme`/`fonts`/`epub`/`editor`；`crossRef`/`katex` 标注为「仅构建层可配」（改 `features.config.mjs`）。
- 每次变化 dispatch `dsh:feature-change`、`astro:page-load` 后重应用。
- 首页 `index.astro` 为独立布局，不带面板，其 EPUB 入口由构建层 `features.epub.enabled` 控制。

## 五、如何新增一个功能（插件接入）

在 `features.config.mjs` 追加一个 `defineFeature({...})`，然后在对应装配处接上挂载点：

1. **声明**：加 manifest（`id`/`cat`/`enabled`/`devOnly`/`ui`）。
2. **build 挂载点**：若需要 rehype/vite 插件 → 在 `astro.config.mjs` 按 `features.<id>.enabled`（或 `isEffective('<id>')`，dev 功能用后者）拼装；需要 CSS → 加入 `customCss`；需要生成脚本 → 脚本内读 `features.<id>.enabled`。
3. **UI 渲染点**：若需向读者暴露控件 → 在目标组件的 frontmatter 读 `features.<id>.enabled` 条件渲染。
4. **性能**：只要第 2/3 步按开关拼装/渲染，关闭即零打包。

> 新增功能无需改散落的 `IS_DEV`/硬编码开关——只需在 registry 声明 + 接到装配处。

## 六、环境坑（DSH 沙箱，本项目已验证）

- 本地 `npm run build` / `astro dev`/`preview`/`sync` 在加载 `astro.config.mjs` 处报
  `source-map-js ... require is not defined`（沙箱限制，非内容/改动问题）。**不要在此沙箱用 astro 引擎启动/预览**。
- 内容正确性用 `node scripts/scan-mdx.mjs`（与构建同款管线）验证；上线正确性靠 `git push` 触发 Vercel。
- 改动涉及 `astro.config.mjs` 需重启 dev server（config 不热更新）；仅改 `.astro`/`.mjs`/`.ts` 时 HMR 热更新。
- `git push` 需 `danger-full-access` 升级（沙箱 fork ssh 被拒）。
