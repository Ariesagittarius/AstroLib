## 一、任务概述

用户反馈：**阅读文章时切换文件（点击左侧侧边栏/翻页切换到另一篇文章）存在异常卡顿，切换时间过长**。

已交付（方案 A，纯客户端优化，4 项，已上线）：

1. 长行内公式"胶囊化"改为**仅移动端执行**，并去掉 `fonts.ready` 后的第二遍全量重测；
2. 引用徽章文本扫描**分片异步化**（requestIdleCallback 分批，正文先渲染）；
3. 公式操作钮（复制 LaTeX / 导出 SVG/PNG）改为 **IntersectionObserver 惰性挂接**；
4. 预取增强：悬停去抖 120ms→50ms、**按下鼠标立即拉取**、翻页链接纳入预取。

另有方案 B（构建期徽章下沉）**已接入上线**（提交 `b7847ac`，见第四节）。

## 二、根因分析（量化数据，勿再重复勘察）

切换卡顿的链路（点击侧边栏 → 新内容出现）主线程同步执行：

1. **fetch + DOMParser 解析整页 HTML**：文章页 HTML 平均 **410KB、最大 2.9MB**（23 页超 1MB、39 页超 800KB），正文(main-pane)占整页 **98%**，单页最多 2637 个 KaTeX 节点、约 13.5 万个标签。fragment 化传输收益极小（主体就是正文）。
2. **`astro:page-load` 同步处理链**（真正的重头）：
   - `tameOverflowingInlineMath()`：对每页 1000+ 行内公式逐个 `getBoundingClientRect()`（强制同步布局），**每次导航执行 2 遍**（立即 + `document.fonts.ready` 后）→ 单次切换最多 **2400+ 次强制重排**，是最大单一开销；
   - `linkPageElements()`：TreeWalker 遍历整页数万个文本节点做正则匹配 + DOM 替换；
   - `initFormulaActions()`：为每页几百~上千个公式逐个创建操作按钮 + 行内公式包宿主（又一次 DOM 变更）；
   - `buildBookTOC()`：选择题重构 + 卡片标题 KaTeX 二次渲染 + 大纲重建。

**结论**：卡顿不是网络问题，而是 ① 大 HTML 的同步解析 + ② 切换后海量同步重排/扫描/渲染 双重叠加。图片已全量 `loading="lazy"`（非瓶颈）；JS/CSS/KaTeX 字体首屏加载后 SPA 切换不重复下载（非瓶颈）。

### 根因（方案 A/B 之后的剩余同步链）

每次 SPA 切换后 `astro:page-load` 处理器仍同步执行一长串工作，阻塞正文首帧绘制：

1. `buildBookTOC()` 内：`compareDocumentPosition` 排序（O(n log n) DOM 遍历比较）、
   桌面+移动两份大纲 DOM 构建、侧边栏/抽屉 `renderMathInElement`（auto-render 公式扫描）、
   逐卡片标题 `renderMathInElement`（math_analysis 有 436 个含 `$` 的卡片标题）、
   `linkPageElements` 徽章升级 + 逐个挂事件、`data-global-index`（约 100KB+）每次 `JSON.parse`；
2. `initFormulaActions()` 每次导航同步 `querySelectorAll` 上千公式节点并逐个 observe。

### 引用开关用法

`src/config/collections.config.mjs` 顶部：

```js
export const siteConfig = { refs: 'interactive' }; // 或 'static'
```

- `interactive`（当前默认）：行为与之前一致（同页/跨页联动），只是处理时机移到空闲时段；
- `static`：构建期 `rehypeCrossRef` 强制静态 chip，`PageSidebarOverride` 不构建/输出
  `data-global-index`（页面 HTML 更小），客户端 `linkPageElements` 直接返回。
  想彻底去掉“卡片引用的建立”开销时用这个。
